# Marketplace Project Rules

## 1. Identifiers
- All entities use `UUID v4` generated by the backend.
- Cross-service references use UUID only. No foreign keys between tables across services.

## 2. Error Handling
- All errors return a uniform object:
  ```json
  {
    "code": "STRING_CODE_IN_SUCH_FORMAT",
    "message": "Readable message for user",
    "details": ["optional validation errors"],
    "correlationId": "uuid"
  }
  ```
- Each service owns its error-code namespace (e.g. `auth.*`, `catalog.*`).
- Frontend and other services switch on `code` only; `message` is for humans.

## 3. Event / Queue Contract
- Every event wrapped as:
  ```json
  {
    "eventId": "uuidv4",
    "eventType": "entity.event",
    "version": 1,
    "occurredAt": "ISO-8601 UTC",
    "correlationId": "uuid",
    "payload": {}
  }
  ```
- **Evolution**: add fields in the same version. Delete/rename only with a new version.
- Consumers ignore unknown fields.

## 4. Idempotency
- Before handling, consumer checks whether `eventId` was already processed.
- After handling, persist the event-idempotency record atomically with the business change.
- Saga commands include `sagaId` (e.g. `orderId`) for deduplication.
- Duplicate events with the same `eventId` are no-op (no error).

## 5. Time
- Use UTC everywhere.
- Use ISO-8601 format.
- All entities have `createdAt` and `updatedAt`.

## 6. Configuration
- All configuration via environment variables.
- Validate configuration on application start.
- Fail fast if configuration is invalid.
